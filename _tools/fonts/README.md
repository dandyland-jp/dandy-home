# Webフォントの運用手順書

DANDY HOME のWebフォントは、Google Fonts から直接読み込まず、サイト内の `/fonts/` から配信しています。
表示速度を上げるため、ページで使っている文字だけを含む小さなフォント（サブセット）を先に読み込み、
それ以外の文字は「予備フォント」で補います。

このフォルダ（`_tools/`）は名前が `_` で始まるため、GitHub Pages では公開されません。

## 構成

| 場所 | 内容 | 手で編集するか |
|---|---|---|
| `fonts/fonts.css` | 最初に読み込むフォントの指定（欧文フォント＋和文サブセット） | しない（自動生成） |
| `fonts/fonts-fallback.css` | 予備フォントの指定。ページ表示後に読み込まれる | しない（自動生成） |
| `fonts/subset/` | 和文サブセット（Noto Sans JP 1ファイル、Shippori Mincho 500/600/700 の3ファイル） | しない（自動生成） |
| `fonts/files/` | 欧文フォント（Manrope / Montserrat / Bodoni Moda）と和文の予備フォント一式（Google Fonts の配信ファイル） | しない（自動生成） |
| `fonts/LICENSE-*.txt` | 各フォントのライセンス文書（SIL Open Font License 1.1） | しない |
| `_tools/fonts/build_fonts.py` | 作り直し用のスクリプト | 必要なときだけ |
| `_tools/fonts/subset-chars.json` | サブセットに入っている文字の一覧（`--check` で使う） | しない（自動生成） |
| `_tools/fonts/latin.css` | 欧文フォントの指定（`fonts.css` の材料） | しない（自動生成） |

書体と太さは従来と同じです（Noto Sans JP 400〜700、Shippori Mincho 500/600/700、Manrope 400〜700、
Montserrat 600/700、Bodoni Moda 700/900）。各ページの `<head>` の読み込み処理はこのフォルダの対象外で、
変更する必要はありません。

## 必要なもの

- Mac の Python 3（標準で入っているもので可。追加のインストールは不要）
- Google Chrome（`/Applications/Google Chrome.app`）
- インターネット接続（`--check` のときは不要）

## 文章・施工事例・ページを追加・変更したとき

1. いつもどおり HTML を編集する。新しいページは、ほかのページと同じ `<head>` のフォント読み込み処理を入れる。
2. 足りない文字があるかを調べる（ファイルは変更されません）。

   ```bash
   python3 _tools/fonts/build_fonts.py --check
   ```

   - `OK：サブセットに足りない文字はありません。` と出たら、フォントの作業はありません。
   - 足りない文字が表示された場合は、手順3へ進む。
3. サブセットを作り直す（1分ほどかかります）。

   ```bash
   python3 _tools/fonts/build_fonts.py
   ```

4. ローカルで表示を確認する（スマホ・PCで、新しい文字が他の文字と同じ書体で表示されているか）。
5. HTML と一緒に、`fonts/fonts.css`、`fonts/subset/`、`_tools/fonts/subset-chars.json` の変更を commit する。

**作り直しを忘れた場合**：表示が崩れたり文字化けしたりすることはありません。サブセットにない文字は、
ページ表示後に予備フォントから正しい書体で補われます（その文字だけ一瞬遅れて切り替わり、
1文字あたり20〜30KB程度の追加の読み込みが発生します）。速度を保つため、気付いた時点で作り直してください。

対象ページは **git に登録済みの HTML** です。未公開のページ（例：commit していない `recruit/index.html`）は
対象外です。未公開のページを公開するときは、そのページを commit する前に `<head>` をほかのページと同じ形にし、
`git add` してから手順3を実行してください（git に登録された時点で対象になります）。

## フォントの版を更新するとき（年に1回程度・任意）

Google Fonts でフォントが更新されても、このサイトには自動では反映されません（表示が勝手に変わらないようにするため）。
更新したいときは、次のコマンドで欧文フォント・予備フォント・ライセンス文書を取り直し、サブセットも作り直します。

```bash
python3 _tools/fonts/build_fonts.py --refresh
```

実行後は、全ページの表示を修正前と比べて確認してから commit してください（字形がわずかに変わる場合があります）。

## しくみ

- スクリプトは対象ページをローカルで表示し、320〜1440px の各画面幅で、すべての文字（閉じた状態のダイアログ、
  擬似要素、入力欄の仮表示文字、`js/*.js` が表示する文言を含む）について、実際に使われる書体と太さを調べます。
- 欧文フォントで表示される基本の英数字・記号（U+0020〜U+007E）以外の文字を、和文サブセットに入れます。
  サブセットは Google Fonts の `text=` 指定で作るため、予備フォントと同じ版・同じ字形です。
- 表示の順番は、ファーストビューの写真 → Webフォント → 予備フォントのCSS・画面外の写真です
  （各ページの `<head>` の処理）。JavaScript が無効な場合は、すべてのフォントを最初から読み込みます。
- サブセットのファイル名には内容から作った識別子が入るため、作り直すと名前が変わり、古いファイルは削除されます。

## ライセンス

5書体とも SIL Open Font License 1.1 です。自社サーバーからの配信、サブセット化（必要な文字の抜き出し）、
Webサイトでの利用が認められています。ライセンス文書は `fonts/LICENSE-*.txt` として同梱しており、
`--refresh` のたびに Google Fonts の公式リポジトリ（github.com/google/fonts）から取り直します。
フォントファイルを販売することは禁止されています（Webサイトでの利用は問題ありません）。
